MASTER DEVELOPMENT PROMPT

ADVANCED AUDIO VISUALIZATION ELEMENT SYSTEM — AVEE PLAYER STYLE

PROJECT OBJECTIVE

Develop a professional, fully functional, highly customizable audio visualization engine inspired by the element-based visualizer architecture of Avee Player.

The application must provide a complete element editor in which users can add, configure, customize, animate, layer, combine and control different visualization components.

The system must include the following seven major element types:

1. Audio Provider
2. Image
3. Rgb Split
4. Blur Effect
5. Bars/Segments
6. Particles
7. Text
8. Motion Blur Effect

Every element must have its own property panel, configuration system, audio-reactive controls, rendering behavior and editing capabilities.

IMPORTANT:

- Preserve the exact property names supplied in this specification.
- Organize properties under their original section and category names.
- Every setting must perform its actual intended function.
- Do not create decorative or nonfunctional controls.
- Support real-time audio reactivity.
- Support independent editing of every element.
- Use a non-destructive layer-based rendering architecture.
- Maintain synchronization between audio playback and visual animation.

1. AUDIO PROVIDER

Purpose

The Audio Provider is the central data source that analyzes incoming audio and generates numerical values for visual elements.

It supplies frequency spectrum samples, beat information, amplitude measurements and processed audio values to connected visualizer elements.

Other elements such as Bars/Segments, Particles, Image and animated effects must be able to receive data from an Audio Provider.

1.1 General

Sample Provider

Purpose: Selects the source responsible for generating visualization data.

Expected functionality:

- Select the sample provider type.
- Support Spectrum as a provider.
- Allow different visual elements to reference an Audio Provider.
- Support multiple provider instances when required.
- Allow users to select the appropriate provider through Audio Provider Index.
- Maintain a consistent provider reference throughout the composition.

System instruction:
The selected provider must analyze the audio and expose processed sample data through a shared audio-analysis interface.

The provider must not independently decode the audio for every visual element.

1.2 Spectrum

Sample Out Count

Purpose: Determines the number of frequency samples generated by the provider.

Functionality:

- Define the total number of output samples.
- Control the resolution of spectrum visualization.
- Support low and high sample counts.
- Distribute frequency samples across the selected frequency range.
- Update connected elements when the count changes.

Working logic:
The engine divides the configured frequency range into the requested number of output samples.

Each sample represents the magnitude of a particular frequency band.

Mirror Samples

Purpose: Mirrors the spectrum sample distribution.

Functionality:

- Enable or disable sample mirroring.
- Generate symmetrical sample arrangements.
- Support left/right mirrored visualization.
- Support symmetrical bar and waveform arrangements.

Working logic:
Generate the original sample sequence and create a mirrored sequence using the configured mirroring behavior.

Do not incorrectly duplicate audio energy when the mode is intended only to mirror visual positions.

Repeat Samples

Purpose: Repeats the available samples to fill the requested output distribution.

Functionality:

- Repeat sample sequences.
- Support repeated frequency patterns.
- Allow repeated visualization arrangements.
- Work with Sample Out Count and Mirror Samples.

Working logic:
When the available sample sequence is shorter than the requested output, repeat the sequence according to the selected repetition behavior.

Star And End Gap (Start and End Gap)

Purpose: Controls the spacing or excluded sample region at the beginning and end of the spectrum distribution.

Functionality:

- Configure start gap.
- Configure end gap.
- Control empty areas at both ends.
- Adjust the visible spectrum distribution.
- Support symmetrical and asymmetrical gap configurations.

Working logic:
Calculate the usable sample region after applying the start and end gaps.

Distribute samples within the remaining range.

Smooth

Purpose: Controls smoothing of the final spectrum output.

Functionality:

- Reduce sudden sample fluctuations.
- Produce stable visual movement.
- Prevent excessively sharp spectrum changes.
- Allow adjustable smoothing strength.

Working logic:
Apply temporal smoothing to the processed sample output.

Use a configurable smoothing algorithm such as exponential interpolation.

Pre Smooth

Purpose: Smooths raw frequency data before subsequent processing.

Functionality:

- Reduce unstable raw FFT measurements.
- Smooth neighboring frequency values.
- Stabilize incoming audio measurements.
- Work independently of final Smooth.

Working logic:
Apply smoothing to raw spectrum magnitudes before frequency remapping, filtering and output amplification.

Filter Radius

Purpose: Controls the number of neighboring samples considered during spectrum filtering.

Functionality:

- Define filtering radius.
- Control the width of neighboring sample influence.
- Reduce abrupt variations.
- Support adjustable filtering strength.

Working logic:
Use a configurable neighborhood filter to calculate each output sample using neighboring frequency samples.

Filter Strength

Purpose: Determines how strongly neighboring samples influence the filtered result.

Functionality:

- Control filtering intensity.
- Smooth irregular spectrum values.
- Preserve or reduce frequency detail.
- Work with Filter Radius.

Working logic:
Interpolate between the original sample and filtered sample according to Filter Strength.

AWeight

Purpose: Applies an A-weighting frequency response curve to the audio spectrum.

Functionality:

- Enable or disable A-weighting.
- Apply frequency-dependent weighting.
- Reduce the contribution of frequencies according to the selected weighting curve.
- Support comparison between weighted and unweighted spectrum.

Working logic:
Apply the standard A-weighting response to frequency magnitudes before final visualization output.

Use actual frequency values and appropriate calibration. Do not approximate A-weighting using arbitrary visual multipliers.

Output Multiplier

Purpose: Amplifies or reduces the final spectrum sample values.

Functionality:

- Increase output magnitude.
- Reduce output magnitude.
- Control overall spectrum intensity.
- Allow individual visualizer elements to apply additional sensitivity.

Working logic:
Multiply processed samples by the configured output multiplier before passing them to connected elements.

1.3 Spectrum Hz

Lower Hz

Purpose: Defines the minimum frequency analyzed by the spectrum provider.

Functionality:

- Set the lower frequency boundary.
- Exclude frequencies below the selected value.
- Focus analysis on bass or other frequency regions.

Higher Hz

Purpose: Defines the maximum frequency analyzed.

Functionality:

- Set the upper frequency boundary.
- Exclude frequencies above the selected value.
- Focus analysis on selected frequency regions.

Hz Linear Factor

Purpose: Controls the distribution of samples across the frequency range.

Functionality:

- Adjust frequency spacing.
- Support linear-like and nonlinear frequency distributions.
- Control how sample positions are distributed between Lower Hz and Higher Hz.

Working logic:
Use a configurable frequency mapping function to distribute sample positions.

Freq Shift

Purpose: Shifts the frequency sampling region.

Functionality:

- Move the sampling range toward higher frequencies.
- Move the sampling range toward lower frequencies.
- Control frequency emphasis.
- Work with Lower Hz and Higher Hz.

Working logic:
Apply a frequency offset or shift to the sampling coordinates while keeping the resulting frequency range valid.

1.4 Beat

Beat Smooth

Purpose: Smooths the beat response signal.

Functionality:

- Reduce unstable beat values.
- Stabilize beat-reactive animations.
- Control beat response smoothness.

Beat Range Bar First

Purpose: Defines the first spectrum sample or bar included in beat-range analysis.

Beat Range Bar Last

Purpose: Defines the final spectrum sample or bar included in beat-range analysis.

Beat Range Value Lower

Purpose: Defines the lower value boundary for beat-range detection.

Beat Range Value Higher

Purpose: Defines the upper value boundary for beat-range detection.

Combined working logic:

1. Read the processed spectrum samples.
2. Select the range between Beat Range Bar First and Beat Range Bar Last.
3. Evaluate the selected frequency sample values.
4. Apply lower and higher threshold boundaries.
5. Calculate the resulting beat intensity.
6. Smooth the result using Beat Smooth.
7. Expose the beat value to connected visual elements.

IMPORTANT:
Implement the beat range as an actual signal-derived measurement. Do not assume every high-amplitude sample is automatically a musical beat.

1.5 Performance

Fft Size

Purpose: Controls the number of samples used for FFT frequency analysis.

Supported configurations:

- 256. 
- 512. 
- 1024. 
- 2048. 
- 4096. 
- 8192. 

Functionality:

- Control frequency resolution.
- Control analysis window size.
- Affect frequency detail and processing cost.
- Allow device-performance-aware configuration.

Working logic:
Use the configured FFT size when processing audio windows.

Larger FFT sizes provide finer frequency resolution but may increase latency and computational cost.

Use suitable windowing functions, such as Hann, to reduce spectral leakage.

Mapping configuration

Every measurement connection must support:

1. Measurement Source.
2. Input Minimum.
3. Input Maximum.
4. Output Minimum.
5. Output Maximum.
6. Multiplier.
7. Offset.
8. Smoothing.
9. Response Curve.
10. Invert.
11. Enable/Disable.

Mapping calculation

Use a normalized measurement:

"normalized = clamp((input - inputMin) / (inputMax - inputMin), 0, 1)"

Then calculate:

"output = outputMin + normalized * (outputMax - outputMin)"

Apply multiplier, offset and smoothing according to the configured processing order.

Handle invalid ranges safely.

- Calculate mapped values.
